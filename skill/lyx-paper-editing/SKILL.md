# Editing LyX papers

Use the `lyx-mcp-server` MCP tools for `.lyx` edits. Make both prose and structural changes through MCP. Do not run the old `check_lyx_changes.py`, splice `\change_*` markers into the source, or rewrite the paper with a separate script. The server starts its own LyX process and does not connect to a desktop instance.

## Efficient revision workflow

Use the four MCP tools: `lyx_read`, `lyx_apply_edits`, `lyx_compare`, and `lyx_job`.
The Python service's older convenience methods are no longer exposed as separate MCP tools.

1. Read state, outline, and the needed passages together with `lyx_read`. Use `selector={"section":"Exact heading"}`, `selector={"node_ids":[...]}`, a `from_node`/`to_before_node` range, or `search`. Request `representations=["text","nodes"]` and add `"source"` when source details matter. Reads parse the saved file without opening LyX. `max_chars`, selector `offset`/`limit`, and `content_offset`/`content_limit` bound the response. Follow `truncated`, `next_offset`, and `next_node_id`; an oversized paragraph can be requested as text only with a smaller content limit. Text contains inset tokens such as `{{formula_VERSION_NUMBER}}`; node metadata identifies formulas, citations, notes, references, and nested paragraphs. A note's text is inspected explicitly through its paragraph IDs, which avoids matching hidden notes by accident.
2. Keep the returned `state.sha256`. Every write requires that exact `expected_sha256`; node IDs belong to that version. Resolve all operations against the same baseline. Give each a unique `id`, and use a paragraph `node_id` whenever possible. Context and an explicit one-based `occurrence` disambiguate repeated text. Preflight reports all invalid operations before modifying anything. After a successful batch, obtain fresh IDs before another write.
3. Send one mixed `operations` batch to `lyx_apply_edits`. Combine wording edits, citations, paragraph operations, and inset changes when their source spans do not overlap. `replace_text` takes `old_text` and `new_text`; `delete_text`, `insert_before`, and `insert_after` cover other text changes. `insert_citation` takes an anchor and bibliography `keys`; use `set_citation` with the citation node to change existing keys. New citations stay separate and tracked, including beside an existing citation. For selections crossing insets, retain their tokens in `new_text` and list the same IDs, in the same order, in `preserve_insets`. This preserves the original inset content rather than deleting and reinserting the formula or reference. A replacement that spans earlier revisions rebases the selected span on its accepted text and reports `rebased_prior_revisions=true`; keep the span narrow to retain unrelated revision history.
4. Express protection in the transaction: `protect=[{"from_node":"...","to_before_node":"..."}]`, `assertions={"unchanged_insets":[...],"only_regions":[...],"tracking_enabled":true}`. Ranges include their start and exclude their end. `validation={"compile":true,"visible_revisions":true,"preserve_unedited_insets":true,"no_unresolved":true}` requests the deliverable checks. Compilation and inset preservation are enabled by default; unresolved citations or references fail compilation. Protect sections that must remain unchanged before editing another section. Inset preservation compares contents and properties, rather than counts.
5. A successful transaction verifies a disposable candidate in isolated LyX, saves it once, compiles once, then commits the target atomically. Set `output_path` to a new allowed `.pdf` path to retain the final marked PDF directly. Inspect per-operation results and `validation`; `compile=false` leaves the document unverified for delivery. The normal response gives state, changed passages, operation results, validation, and build handles, without a full manuscript or log.
6. Reuse `build.build_id`. `lyx_read(path=...,build_id=...,artifact="latex"|"log"|"aux"|"bbl"|"pdf"|"manifest")` retrieves retained outputs; the manifest includes all files, diagnostics, dependency fingerprints, and bibliography/reference mappings. Limit textual artifacts with `content_offset`/`content_limit`. Add a new `output_path` to copy an artifact. `lyx_read(validate=true)` checks revision settings and reuses a current build; dependency changes invalidate reuse. Native whole-document `format="text"` or `"latex"` remains available explicitly and returns bounded content and an artifact handle. Scoped representations are text/source/nodes; scoped native LaTeX exports are not implemented.

Slow operations return `job_id` and a running status after bounded `wait_sec` (default one second). Call `lyx_job(action="wait",wait_sec=...)` with at most 30 seconds, or inspect/cancel it. Back off when the stage is unchanged. The end-to-end `timeout_sec` includes queueing and IPC. After interruption, wait for a terminal result and inspect `transaction_status`, `retry_safe`, and `recovery`. A committed operation must not be resubmitted; a verified rollback permits a fresh read and a corrected retry. An external conflict requires review. Build handles remain available through internal LyX restarts, but session artifacts are temporary unless copied to a final path.

## Structural changes and selective reapplication

Use `split_paragraph` with `node_id` and `after_text`; `join_paragraphs` with adjacent `node_id` and `next_node_id`; `set_layout` with a layout name; or `move_passage` with `from_node`, `to_before_node`, and `before_node`. These operations retain surrounding text revisions. A split restores the active revision state and author in the following paragraph; joins reset the paragraph boundary state before retaining the second paragraph's own markers. LyX does not visibly track these structural changes; the result reports `visibly_tracked=false`. Review their position and layout in the final PDF.

Use `edit_formula` with a formula node and complete LyX math content such as `$x^{2}$`. Use `set_reference`/`set_inset_properties` with a supported `properties` dictionary. `edit_table_cell` uses a table node, zero-based `row`/`column`, and `new_text`; `set_caption` uses a caption node and `new_text`. Multi-paragraph cells/captions require selecting their individual paragraph nodes. For an already reviewed structural revision, `import_revision_range` belongs in the same mixed batch and still requires `source_path`, `source_sha256`, and unique `start_heading`/`end_heading` Sections. It replaces the whole range, so review every change in that range. `normalize_revisions` takes the revision `author_id` and `timestamp` and can share a batch when its source changes do not overlap other operations. Unsafe resizebox ERT normalization reports a structural formatting change rather than a visible text revision.

For selective reapplication, call `lyx_compare(path=current,revised_path=previous,base_path=base)`. Its small text hunks include unchanged context and conflicts. Reapply selected safe hunks with `{"id":"...","op":"apply_hunk","compare_id":"...","hunk_id":"..."}` in a version-checked transaction. Current-author changes are retained. Paragraph restructuring, layout changes, and changed inset contents require explicit operations and remain reviewable conflicts. Never resolve a conflict by replacing a whole Section without reviewing the author's newer work.

Optional PDF inspection uses `lyx_read(...,pdf={"path":"...pdf","action":"annotations","pages":[1,2]})` or `action="render"`. It requires the server's `pdf` extra (PyMuPDF). Annotation results contain type, comment, selected text, page coordinates, nearby context, and confidence-scored manuscript matches. Matches require review; a caret or strikethrough is a prescribed local instruction when the user says tutor comments take priority. Rendered page handles support visual inspection without another compilation.

## Choosing the revision span

Scoped text decodes LyX sentence-ending marks as periods, including inline and separate-line `\SpecialChar endofsentence`. Use the returned visible punctuation in anchors and replacements. An insertion-only `replace_text` can use punctuation or whitespace beside an inset as its original target; explicit insertion operations remain useful when the intent is clearer that way. Caption text can be extended with ordinary text operations while retaining its label inset.

Choose the smallest continuous span that expresses what changed to a reader. Do not turn a sentence rewrite into an alternating series of word deletions and insertions merely because a word-level diff can align some words.

- **One word or inflection:** Replace the whole word and preserve the rest of the sentence. For `achieve → achieves`, do not delete and reinsert the sentence. The server narrows shared prefixes and suffixes while protecting whole-word boundaries.
- **One continuous phrase:** Replace adjacent words that form one changed idea in a single edit. A short unchanged connector may belong inside the span when that makes the marked PDF readable. Avoid a separate revision for every word.
- **A sentence rewrite:** If the argument, structure, or most words change, replace the sentence once. Do not pair old and new words by position. Conversely, one changed word does not justify marking an otherwise unchanged sentence.
- **Separated changes:** Split edits across substantial unchanged text, different sentences, paragraphs, or inset boundaries. When a change spans formulas or citations, retain their typed inset tokens and IDs.
- **Read the marked result:** Inspect LaTeX or the PDF with `\output_changes true`. If a sentence rewrite appears as many adjacent `\lyxdeleted{...}\lyxadded{...}` fragments, combine the revision. If a small correction marks a long sentence, narrow it. Use a `normalize_revisions` operation for existing fragmented revisions, never the old checking script.

In ordinary LyX prose and captions, write numeric ranges with one ASCII hyphen, such as `3-7`. Reserve TeX dash syntax such as `3--7` for raw LaTeX/ERT where appropriate. Treat a range correction as one contiguous revision.

`\change_inserted`, `\change_deleted`, and `\change_unchanged` switch LyX revision state; they are not ordinary TeX macros to concatenate by hand. Deleting or inserting an unmatched ERT macro opening such as `\resizebox{...}{!}{` can make TeX parsing fail when `\output_changes true`.

## Delivery checks

Confirm `validation.content_verified`, `validation.revisions_verified`, revision settings, successful compilation, and the per-operation tracking notes. Verification checks both revision projections and accepted revision status, author identity, and timestamps. LyX may renumber author IDs or omit an empty email field without changing attribution. Inspect the marked PDF and relevant LaTeX/log excerpts from the retained build. Use the manifest's citation/reference mappings when reproducing numbered excerpts. Preserve the author's completed sections and explicit tutor edits, and distinguish prescribed wording from general structural suggestions.

Record the final SHA256, build ID, retained PDF path, and remaining review items. Keep production references read-only when the user authorizes copies or excerpts only; use isolated copies and verify original hashes. Retain the bibliography names used by the manuscript when copying symlinked inputs, and copy external-document reference maps such as an appendix `.aux`; build reuse checks these dependencies too. Do not edit a reference merely to test a capability.
